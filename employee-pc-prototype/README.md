# Remote Professional Local Agent - Windows setup

This is a Windows-only guided installer for the employee-managed Chrome prototype. It does not connect to RPportal and is not a production lead-acceptance system.

## One-time install

1. Download the Windows prototype ZIP and extract the complete folder.
2. Double-click Install-Redfin-Agent.cmd. It installs into your Windows user profile, downloads the official Node.js runtime, verifies its SHA-256 checksum, creates a device token, and adds desktop and automatic-start shortcuts.
3. Enter the assigned employee ID. If you have the webhook URL for the existing Vonage Browser Results Make scenario, you may enter it once. Leaving it blank configures local-only mode. The webhook URL is a secret; keep it private.
4. The installer opens Chrome extensions. Enable Developer mode, select Load unpacked, and choose the installed extension folder printed by the installer. Employee-managed Chrome requires this one-time approval.
5. Run Test-Redfin-Agent.ps1 from the installed folder to check local health and configuration.

## Everyday use

The agent starts automatically at Windows sign-in. Use the Remote Professional Agent desktop shortcut to start it manually. Keep the agent process running and the Chrome extension enabled when testing.

## Safe test behavior

The Vonage-to-Make URL capture and existing Vonage Browser Results bridge are preserved. The agent polls every 10 seconds for at most five minutes, accepts at most one remote job, and forces testOnly=true. The public Redfin homepage should report not_a_lead_page. The prototype is read-only and must never click Accept Lead.

## Troubleshooting

- Health check fails: ensure the agent is running and port 8765 is available.
- Chrome is not connected: open chrome://extensions, ensure the unpacked extension is enabled, and inspect its service worker errors.
- Make is not configured: rerun the installer and enter the existing webhook URL. Do not paste it into tickets, chat, or source files.
- 401/403 errors: confirm local settings and extension configuration were generated by the same installation. Do not disable authentication or broaden CORS as a workaround.
- Repair: run the installer again from the extracted package. Valid local settings are preserved.

## Safety and limitations

- This remains a prototype. Durable cloud queues, leases, multi-computer coordination, and production retries are not implemented.
- The Make webhook is a bearer secret stored locally; it must never be embedded in the public installer or committed.
- No real lead actions are part of this installer phase. Future automation requires explicit written authorization and a separate security review.
- Generated local-settings.json and extension/config.local.js must never be committed or shared.
